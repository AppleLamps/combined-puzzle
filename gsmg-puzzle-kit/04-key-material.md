# Key material

Current as of 29 September 2026. Every address, hash160 and public key below was regenerated by script from its preimage or from the prize public key, and every base58check string was validated. The machine-readable form is `keys.json`. Balances and transaction counts come from mempool.space, pulled on 2026-09-29.

**Derivation convention.** For a phrase-derived key the private scalar is `sha256(UTF-8 phrase)`, and the address is the P2PKH of the compressed public key. Scalar 1 gives hash160 `751e76e8199196d454941c45d1b3a323f1433bd6`, which is the control any implementation should reproduce first. The prize address is the exception: it is the P2PKH of the uncompressed form of its public key.

## The four elliptic-curve neighbours

The 2021-07-18 transaction `a82052a216cad8f5...` (block 691563, OP_RETURN `GSMG.io neighbors, half and double`) paid 5000 sat to each of four addresses. Each is the address of the uncompressed public key obtained from the prize public key P by one curve operation. Each holds exactly its 5000 sat in one transaction and has never spent, so no private key or signature is available for any of them.

If k is the prize scalar, these are the addresses of k-1, k+1, k/2 and 2k. A derived scalar one step from k would land on one of them and miss the prize, so the win test carries their hash160s as near-miss targets. The funding pattern (P plus or minus G, half, double) is the pattern ECDLP work uses.

## Reproducing this file

The private-key derivations, the neighbour transforms and the base58check strings need no network. A short script over `hashlib` and any secp256k1 implementation regenerates every address here, and the checkpoint set can be re-checked live with the function in `claude/21-checkpoint-oracle.md`.
