## 2. DBBI is a substituted SHA-256 hex digest (L5)

**Exact (L5)**
- Tokenise DBBI so that letters `b` and `g` start 2-character tokens and all other letters are single tokens. This gives exactly **64 tokens using 16 distinct codes**, the shape of a hex SHA-256.
- Of the 36 a–i letter pairs, **only `bg`** does this.
- The equality pattern (first-seen order) is `01234556728966286abc61c88b48de3086dd501d5557d6bab5605233df7bbb96`.

**Caveats**
- The statistic was chosen after looking. About 0.3% of letter-count-preserving shuffles give 64/16 for *some* pair (304 / 100,000). Another run with a different control reported 209 / 20,000 (~1%) [log]; quote the control you use.
- The token → hex-digit mapping is unknown.
- Origin: `prior_research_ledgers/newest_9926_dbbi_hex/PROGRESS.md`. Its helper scripts are not in the folder; L5 plus `check_candidate.py` replace them.

**How to test**
- `check_candidate.py` checks every candidate answer. If sha256(answer) has the same repeat pattern, it prints `[DBBI-PATTERN MATCH]`. A random match has chance 16!/16^64 = 2^-211.7 (earlier text said ≈ 2^-100, which is conservative).
- **Back-check 2026-09-13:** every string still on disk from earlier rounds and session logs (16.8 M strings, 11 forms, 4 hash views, 3 orientations) gave **0 matches** (`runs/2026-09-13_l5_backcheck/`; stopped at 4,443/4,444 jobs; 8/8 planted controls). Generated candidates that were never saved are not covered.
- If a match is found, the mapping falls out and DBBI becomes "sha256 of <answer>". That would fit the SalPhaseIon literals `shabef…` / `shabefanstoo`.
