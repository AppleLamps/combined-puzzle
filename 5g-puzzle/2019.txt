HOW TO READ THIS FILE
--------------------------------------------------------------------------------
Days begin with:      ## DAY YYYY-MM-DD (Weekday)
Each message block:   [#<id>] HH:MM:SS <Display Name> (<user id>)
                      (annotation lines, zero or more, in parentheses)
                      <message text, may span several lines>
Blocks are separated by a blank line. Times are HH:MM:SS under the DAY
date above them, in the timezone the export was taken in.

#<id> is the Telegram message id. It is unique across the whole export and
increases with time, so replies can be traced across files by id.

Annotation lines you may see:
  (reply to #N - Author: "quoted snippet")   this message answers #N;
     a [YYYY-MM-DD] after the id means #N is from another day/file
  (forwarded from X) / (sent via bot @b) / (edited YYYY-MM-DD HH:MM:SS)
  (attachment: ...)  media was posted; the binary is NOT part of this export
  (poll: "question" ...)                     a poll and its vote counts
  (reactions: EMOJI xN, ...)                 emoji reactions on the message
Lines starting with  * SERVICE  are membership events, not chat messages.

Author names are normalised: a given user id always appears under the same
display name (the one they used most often), so a person stays recognisable
even where the raw export recorded no name for a message.
Inline `code` and fenced ``` blocks preserve the original code formatting.
